# Ledger reconciler

`reconcileLedger(entries)` returns `{ totals, metrics }`. `entries` must be an array; each unusable row increments `invalidCount`. A usable row is an object with a non-empty `id`, `accountId`, and `currency`; type `sale` or `refund`; a valid money amount; and a valid date accepted by `new Date`. Any occurrence of an ID after its first occurrence is ignored entirely and increments `duplicateCount` (including duplicate refunds). The first occurrence is the only one considered for validation and processing.

Money is a non-negative decimal string with an optional leading `$`: digits with no commas, or correctly grouped thousands commas (for example `1,200.05`); it may have zero, one, or two fractional digits. It must be represented exactly in cents with no rounding. Negative values, malformed comma grouping, and more than two decimals are invalid. `parseAmountToCents` throws for invalid amounts.

Totals group processed rows by `accountId`, `currency`, and the UTC calendar day (`YYYY-MM-DD`) of their own `createdAt`. A sale adds its amount and is remembered by ID. A refund must name an already processed sale in `originalId`; it subtracts its amount on the refund's UTC day, using the original sale's account and currency. A refund without such a sale increments `orphanRefundCount` and does not affect totals. `processed` counts only rows that affect totals. Totals retain `{ accountId, currency, day, netCents, count }`, where `count` is processed rows in that group, and are sorted by account, currency, then day. The exported function names and result shape must remain unchanged. Use Node built-ins only.

## Defects and fixes

**1. Money parsing was lossy and over-permissive** — `fixtures/phase1-ledger/src/reconcile.js:7`
`Number(normalized)` + `Math.round(value * 100)` accepted negatives (`-1.00`), empty/whitespace strings (`Number('') === 0`), scientific notation (`1e3`), and silently *rounded* over-precise input (`'1.005'` → `100`) rather than rejecting it. Replaced with an anchored regex `^(\d+)(?:\.(\d{1,2}))?$` and integer arithmetic on the captured groups. This also sidesteps float error entirely — no `value * 100` multiplication, so `'1.15'` yields exactly `115`.

**2. Day grouping used local time, not UTC** — `:21`
`toLocaleDateString('en-CA')` produces `YYYY-MM-DD` but in the **runtime's** timezone, so the same input bucketed into different days depending on the host. Switched to `toISOString().slice(0, 10)`, which is UTC by definition.

**3. Duplicate ids were counted but still applied** — `:56`
`duplicateCount` incremented, then execution fell through and the duplicate hit `addTotal` anyway. Added `continue`. Placement matters: the skip sits *before* `parseAmountToCents`, so a duplicate carrying a malformed amount counts as a duplicate rather than leaking into `invalidCount` — matching first-write-wins semantics.

**4. Refunds posted to the wrong account/currency** — `:73`
Used `entry.accountId`/`entry.currency` from the refund row. Spec requires the *original sale's* account and currency (with the refund's own day). Changed to `original.accountId`/`original.currency`.
